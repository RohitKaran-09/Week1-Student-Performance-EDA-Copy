This Week 4 project demonstrates the development and evaluation of machine-learning classification models in Python using the official Student Performance Mathematics dataset from the UCI Machine Learning Repository. The business-style question is whether information about student background, study habits, attendance, and previous class failures can help identify students who reach a descriptive final-grade threshold of 10 out of 20. This cutoff is used only for the project and should not be assumed to represent every institution's grading policy.

The Python workflow acquires the official dataset, checks required fields, removes duplicate records, converts numeric variables safely, validates plausible ranges, and records any exclusions. The final grade is transformed into a binary target. To avoid target leakage, the earlier course grades G1 and G2 are intentionally excluded from the predictors, because they are very closely related to the final grade and may not be available at the intended time of prediction. Missing numeric values are handled by median imputation and numeric scaling; missing categorical values are handled by most-frequent imputation and one-hot encoding. These transformations are fitted inside Scikit-learn pipelines so that information from the held-out test set does not leak into training.

Three models are compared: Logistic Regression, a Decision Tree, and a Random Forest. A stratified train-test split is created before model selection. Stratified five-fold cross-validation on the training set compares models using ROC-AUC, and the best mean cross-validated model is evaluated once on the held-out test set. The report includes accuracy, precision, recall, F1-score, ROC-AUC, a confusion matrix, a ROC curve, and a comparison chart of model performance. Feature importance or model coefficients are also visualized to support interpretation.

The report critically discusses false positives, false negatives, overfitting, class balance, small sample size, and the limitations of using data from two Portuguese secondary schools. Since the records are observational, the model is an educational exercise and must not be treated as a definitive decision tool for individual students. The repository contains reproducible code, dependencies, charts, evaluation results, an audit file, and the final Word report.
